Sometimes you need a value of one type to behave as another. A **cast** tells Java to convert it.

## Casting

```java
double d = 7 / 2;            // 3.0 (integer division happens first)
double e = (double) 7 / 2;   // 3.5 (7 becomes 7.0 first)
int f = (int) 3.99;          // 3   (truncates)
int g = (int) (3.6 + 0.5);   // 4   (rounding)
```

Java converts an `int` to a `double` automatically (widening), but going from `double` to `int` needs an explicit cast because information can be lost.

## Rounding

| Value | Round to nearest int |
| --- | --- |
| positive `x` | `(int) (x + 0.5)` |
| negative `x` | `(int) (x - 0.5)` |

## Range and overflow

An `int` holds values from `Integer.MIN_VALUE` (-2,147,483,648) to `Integer.MAX_VALUE` (2,147,483,647). Exceeding the range **overflows**: `Integer.MAX_VALUE + 1` becomes `Integer.MIN_VALUE`.

<Note title="Where the cast goes matters">
`(double) (7 / 2)` is 3.0, because the integer division happens before the cast. `(double) 7 / 2` is 3.5, because the cast applies to 7 first.
</Note>

<WorkedExample title="Averages">
`int total = 17; int count = 4;` Which expression gives 4.25?

1. `total / count` is 4 (integer division).
2. `(double) (total / count)` is 4.0.
3. `(double) total / count` is 17.0 / 4 = 4.25.

**Answer:** `(double) total / count`.
</WorkedExample>

## On the practice exams

These are the kinds of questions the practice exams ask about this topic. Each has a full answer, the reasoning, and the reason each wrong option is wrong. If you can do all of them without looking, you are ready for this topic on the exams.

### Worked exam question 1

Consider the following code segment.

```java
int total = 47;
int count = 5;
double avg1 = total / count;
double avg2 = (double) total / count;
System.out.println(avg1 + " " + avg2);
```

What is printed as a result of executing the code segment?

**Answer:** `9.0 9.4`

**Why:** avg1 divides two ints before converting; avg2 casts first.

**Working:** `total / count` is integer division (9), then widened to 9.0. `(double) total / count` casts first, giving 9.4.

**Mistakes to avoid**

- `9.4 9.4`: In avg1 the division happens between two ints, so the decimal part is lost before the result is stored.
- `9.0 9.0`: The cast in avg2 applies to total before dividing, so the division is done with doubles.
- `9 9.4`: avg1 is a double, so it prints with a decimal point.
