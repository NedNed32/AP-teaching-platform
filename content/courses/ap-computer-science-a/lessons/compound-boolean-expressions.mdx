Real conditions often combine several tests: "the password is long enough **and** contains a digit". Logical operators join boolean expressions.

## Truth tables

| `a` | `b` | `a && b` | `a \|\| b` | `!a` |
| --- | --- | --- | --- | --- |
| true | true | true | true | false |
| true | false | false | true | false |
| false | true | false | true | true |
| false | false | false | false | true |

Precedence: `!` first, then `&&`, then `||`.

## Short-circuit evaluation

- `a && b`: if `a` is false, `b` is not evaluated.
- `a || b`: if `a` is true, `b` is not evaluated.

This prevents errors: `if (s != null && s.length() > 0)` never calls a method on a null reference.

<Note title="Ranges need two comparisons">
Java does not allow `1 < x < 10`. Write `x > 1 && x < 10`.
</Note>

<WorkedExample title="Evaluate with precedence">
With `int a = 3, b = 8;`, evaluate `a > 5 || b > 5 && a % 2 == 0`.

1. `&&` first: `b > 5` is true, `a % 2 == 0` is false, so `true && false` is false.
2. Then `a > 5 || false` is `false || false`.

**Answer:** false.
</WorkedExample>

### Worked exam question 1

Consider the following Boolean expression.

```java
(x > 6 && y < 7) || x == y
```

For which of the following values is the expression `true`?

**Answer:** `x = 7, y = 0`

**Why:** Substituting these values makes the whole expression true.

**Working:** With x = 7 and y = 0, evaluating `(x > 6 && y < 7) || x == y` step by step gives true; each other pair gives false.

**Mistakes to avoid**

- `x = 12, y = 11`: Substitute and evaluate each part: this pair makes the expression false.
- `x = 4, y = 10`: Substitute and evaluate each part: this pair makes the expression false.
- `x = 9, y = 11`: Substitute and evaluate each part: this pair makes the expression false.

### Free-response practice: Parking fees

A parking garage charges for each stay as follows.

• Stays of 15 minutes or less are free.

• Otherwise the fee is 4 dollars for each hour or part of an hour (so 61 minutes counts as 2 hours).

• No stay costs more than 24 dollars.

```java
public class Garage {
    /** Returns the fee, in dollars, for a stay of the given length. Precondition: 0 <= minutes <= 1440 */
    public static int fee(int minutes) { /* part (a) */ }
    /** Returns the longest stay, in minutes from 0 to 1440, whose fee is at most budget. */
    public static int longestStay(int budget) { /* part (b) */ }
}
```

Examples: `fee(15)` returns 0, `fee(22)` returns 4, `fee(163)` returns 12, `fee(840)` returns 24. `longestStay(16)` returns 240.

**(a)** Write the method `fee`.

To earn the point: Returns 0 for stays of 15 minutes or less. Model answer: `if (minutes <= 15) return 0;`

To earn the point: Counts hours, rounding any partial hour up. Model answer: `int hours = (minutes + 59) / 60;`

To earn the point: Applies the 24-dollar maximum and returns the fee. Model answer:

```java
public static int fee(int minutes) {
    if (minutes <= 15) {
        return 0;
    }
    int hours = (minutes + 59) / 60;
    int cost = hours * 4;
    if (cost > 24) {
        cost = 24;
    }
    return cost;
}
```

**(b)** Write the method `longestStay`. Assume `fee` works as specified, regardless of what you wrote in part (a).

To earn the point: Examines stay lengths from 0 to 1440 (in either direction). Model answer: `for (int m = 1440; m >= 0; m--)`

To earn the point: Calls fee and compares the result with budget. Model answer: `if (fee(m) <= budget)`

To earn the point: Returns the longest qualifying length. Model answer:

```java
public static int longestStay(int budget) {
    for (int m = 1440; m >= 0; m--) {
        if (fee(m) <= budget) {
            return m;
        }
    }
    return 0;
}
```

### Free-response practice: Terrain peaks

A `Terrain` stores heights in a 2D array. A cell is a **peak** if its height is strictly greater than each of its neighbors above, below, left and right that are inside the grid.

```java
public class Terrain {
    private int[][] heights;
    /** Returns true if the cell at (r, c) is a peak. Precondition: (r, c) is in the grid. */
    public boolean isPeak(int r, int c) { /* part (a) */ }
    /** Returns the number of peaks in the grid. */
    public int countPeaks() { /* part (b) */ }
}
```

For the grid below, `isPeak(2, 1)` returns false and `countPeaks()` returns 6.

```java
 7  8  6  9  5
 1  9  6  3  9
 9  5  4  2  4
 6  9  5  8  6
```

**(a)** Write the method `isPeak`.

To earn the point: Checks each of the four neighbors. Model answer: above, below, left and right

To earn the point: Checks bounds before reading a neighbor, so edge cells do not cause an exception. Model answer: `r > 0 && heights[r - 1][c] >= h`

To earn the point: Uses strict comparison and returns the correct boolean. Model answer:

```java
public boolean isPeak(int r, int c) {
    int h = heights[r][c];
    if (r > 0 && heights[r - 1][c] >= h) return false;
    if (r < heights.length - 1 && heights[r + 1][c] >= h) return false;
    if (c > 0 && heights[r][c - 1] >= h) return false;
    if (c < heights[0].length - 1 && heights[r][c + 1] >= h) return false;
    return true;
}
```

**(b)** Write the method `countPeaks`. Assume `isPeak` works as specified, regardless of what you wrote in part (a).

To earn the point: Traverses every cell with nested loops and correct bounds. Model answer: `for (int r = 0; r < heights.length; r++) for (int c = 0; c < heights[0].length; c++)`

To earn the point: Calls isPeak on each cell. Model answer: `if (isPeak(r, c)) count++;`

To earn the point: Returns the count. Model answer:

```java
public int countPeaks() {
    int count = 0;
    for (int r = 0; r < heights.length; r++) {
        for (int c = 0; c < heights[0].length; c++) {
            if (isPeak(r, c)) {
                count++;
            }
        }
    }
    return count;
}
```
