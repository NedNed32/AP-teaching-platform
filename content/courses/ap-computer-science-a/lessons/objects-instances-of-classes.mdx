Object-oriented programming models a program as a set of interacting objects. Each object is built from a **class**.

## Class versus object

| | Class | Object |
| --- | --- | --- |
| What it is | a blueprint | a thing built from the blueprint |
| Example | `Car` | your car, my car |
| How many | one definition | any number of instances |

## State and behavior

- **Attributes (state):** data each object stores, in instance variables. A `Car` might have `color` and `mileage`.
- **Behaviors:** what objects can do, as methods. A `Car` might `drive(int miles)`.

Each object has its own values for the attributes, but all objects of a class share the same methods.

<Note title="Classes describe, objects exist">
A class does not hold data about any particular car until you create an object from it with `new`.
</Note>

<WorkedExample title="Designing attributes and behaviors">
Suggest two attributes and two behaviors for a `BankAccount` class.

1. Attributes: `balance` (double), `owner` (String).
2. Behaviors: `deposit(double amount)`, `getBalance()`.

**Answer:** state is the data each account stores; behaviors are the operations the account supports.
</WorkedExample>

## On the practice exams

These are the kinds of questions the practice exams ask about this topic. Each has a full answer, the reasoning, and the reason each wrong option is wrong. If you can do all of them without looking, you are ready for this topic on the exams.

### Worked exam question 1

Assume a class `Point` has a constructor `Point(int x, int y)`, a method `setX(int x)` and a method `getX()`. What is printed by the following code segment?

```java
Point p = new Point(21, 1);
Point q = p;
q.setX(18);
p = new Point(4, 7);
System.out.println(q.getX() + " " + p.getX());
```

**Answer:** `18 4`

**Why:** q and p first refer to the same object; then p is pointed at a new object, and q is unaffected.

**Working:** After q = p, both refer to one Point whose x becomes 18. Then p refers to a new Point (x = 4); q still refers to the first one.

**Mistakes to avoid**

- `21 4`: q = p copies the reference, so q.setX changes the shared object.
- `4 4`: Reassigning p does not change what q refers to.
- `18 18`: p now refers to a new Point with x = 4.

**A.** `variable VARIABLE`. Strings are immutable; calling a method without storing its result changes nothing. String methods return new Strings. Unless the result is assigned, the original variable is unchanged.
