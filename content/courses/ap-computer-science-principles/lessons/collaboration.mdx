Most software is built by teams. Collaboration is not just convenient; it changes what gets built.

## Why collaborate

- **Diverse perspectives** reveal needs and problems one person would miss, and reduce bias in the result.
- Teams can divide large problems and work in parallel.
- Reviewing each other's work catches errors early.

## Practices

- **Pair programming**: a driver types; a navigator reviews and thinks ahead. Swap often.
- **Consulting users** through surveys, interviews and testing.
- Giving and receiving **constructive feedback**.
- Using shared tools: version control, shared documents, comments in code.

<Note title="Credit your collaborators">
Program code written by someone else, including a partner, should be acknowledged. On the Create performance task, you must identify code that you did not write.
</Note>

<WorkedExample title="Improving an app with feedback">
A team builds a bus-schedule app. Testing with older riders shows the text is too small. What does this illustrate?

1. The developers did not share this need, so they missed it.
2. Input from a different group of users exposed the problem.

**Answer:** gathering diverse perspectives improves a computing innovation.
</WorkedExample>

## On the practice exams

These are the facts and ideas the practice exams ask about this topic, each with the answer and the reason. If you can answer all of them without looking, you are ready for this topic on the exams.

### Facts and ideas the exams test

Cover the answers and test yourself.

**Q.** After user testing reveals problems, a developer returns to the design phase and revises the plan before writing more code. Which approach does this describe?

**A.** Iterative development. Revisiting earlier phases based on feedback is iterative development.

**Q.** In an event-driven program, when does the code attached to a button run?

**A.** When the button-click event occurs. Event-driven code runs in response to events.

**Q.** Two students work at one computer: one types the code while the other reviews each line and plans the next step, and they switch roles often. What is this practice called?

**A.** Pair programming. A driver and a navigator working together is pair programming.

**Q.** Which of the following is the best reason to include people with diverse backgrounds on a team designing an app?

**A.** They can identify needs and possible biases that a less diverse team might miss. Diverse perspectives improve computing innovations.

**Q.** A team builds a small part of an app, tests it, then adds another small part and tests again. Which development approach is this?

**A.** Incremental development. Adding and testing one small piece at a time is incremental.

**Q.** What is the primary purpose of comments in program code?

**A.** To explain how the code works for people reading it, without affecting how it runs. Comments are documentation for programmers.

**Q.** A programmer uses a procedure that was written by another student. What should the programmer do?

**A.** Acknowledge the other student as the author of that code. Code written by others should be credited.

**Q.** A weather app's purpose is to help people plan their day. Which statement describes the app's function rather than its purpose?

**A.** It takes a location as input and displays the forecast for that location. Function describes what the program does: its inputs and outputs.
