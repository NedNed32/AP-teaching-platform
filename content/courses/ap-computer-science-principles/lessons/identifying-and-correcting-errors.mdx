Errors are a normal part of programming. Knowing the types makes them easier to fix.

## Types of errors

| Error | When it appears | Example |
| --- | --- | --- |
| syntax | before running | missing parenthesis |
| run-time | while running | dividing by zero |
| logic | program runs, wrong result | a comparison written backward |
| overflow | a number too large for its storage | exceeding the largest value a fixed number of bits can hold |

## Finding errors

- **Test cases**: choose inputs with known expected outputs, including boundary values and unusual inputs.
- **Hand tracing**: step through the code, tracking variable values.
- **Visualizations** and **debuggers**.
- Extra **output statements** that display intermediate values.

<WorkedExample title="Fixing a logic error">
This code should find the largest value in a list of positive numbers, but it always gives 0.

```text
max ← 0
FOR EACH n IN list
{
   IF (n < max)
   {
      max ← n
   }
}
DISPLAY (max)
```

1. n is never less than 0, so max never changes.
2. The comparison is reversed.

**Answer:** change the condition to `n > max`.
</WorkedExample>

## On the practice exams

These are the kinds of questions the practice exams ask about this topic. Each has a full answer, the reasoning, and the reason each wrong option is wrong. If you can do all of them without looking, you are ready for this topic on the exams.

### Worked exam question 1

The following code segment is intended to display the number of elements in `nums` that are greater than 14.

```text
count ← 0
FOR EACH n IN nums
{
   IF (n ≥ 14)
   {
      count ← count + 1
   }
}
DISPLAY (count)
```

When `nums` is `[23, 14, 18, 22, 12]`, the code displays 4 instead of 3. Which change corrects the error?

**Answer:** Change `n ≥ 14` to `n > 14`

**Why:** The value 14 itself is counted but should not be.

**Working:** The list contains 14, which ≥ counts but > does not. Using a strict comparison gives 3.

**Mistakes to avoid**

- Change `count ← 0` to `count ← 1`: That would add 1 to every result.
- Change `n ≥ 14` to `n ≤ 14`: That counts the small values instead.
- Move `DISPLAY (count)` inside the loop: That displays partial counts but does not fix the comparison.

### Worked exam question 2

The following code segment is intended to display the sum of the values in `nums`.

```text
FOR EACH n IN nums
{
   total ← 0
   total ← total + n
}
DISPLAY (total)
```

What is displayed when `nums` is `[6, 13, 20, 3]`, and why?

**Answer:** 3, because total is reset to 0 on every pass

**Why:** The reset inside the loop discards the earlier values.

**Working:** Each pass sets total to 0 and then adds n, so only the last value, 3, remains. Moving `total ← 0` before the loop fixes it.

**Mistakes to avoid**

- 42, because every value is added: total is set back to 0 before each addition.
- 0, because total is reset after the loop: The reset happens before the addition in each pass.
- 6, because the loop stops after one pass: FOR EACH visits every element.

**Q.** A shopping app applies a discount to orders under 50 dollars instead of orders over 50 dollars. Which type of error is this?

**A.** A logic error. The program runs, but the algorithm produces incorrect results.

**Q.** A keyword is misspelled, so the program cannot be translated and run. Which type of error is this?

**A.** A syntax error. The rules of the language are broken, so the program cannot run at all.

**Q.** A program crashes when a user enters 0 because it divides by the number entered. Which type of error is this?

**A.** A run-time error. The error occurs while the program is running and stops it.

**Q.** A program stops partway through when it tries to access the 11th element of a list that has 10 elements. Which type of error is this?

**A.** A run-time error. The error occurs while the program is running and stops it.

**Q.** A step counter that stores totals in 16 bits shows a small number after a user walks a very long way. Which type of error is this?

**A.** A overflow error. The value is larger than the fixed number of bits can represent.
