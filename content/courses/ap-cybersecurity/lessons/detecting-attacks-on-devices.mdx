## Authentication logs

```text
Mar 03 02:14:01 sshd: Failed password for admin from 198.51.100.23
Mar 03 02:14:03 sshd: Failed password for admin from 198.51.100.23
Mar 03 02:14:05 sshd: Failed password for admin from 198.51.100.23
Mar 03 02:14:09 sshd: Accepted password for admin from 198.51.100.23
```

Repeated failures from one address followed by success indicate a likely compromised account.

## Other indicators

- Unknown processes or services; programs running from temporary folders.
- New user accounts or added administrator rights.
- Changed file permissions or modified system files.
- Disabled antivirus or logging.
- Unexpected outbound connections.

## Responding

Isolate the device, preserve evidence, reset credentials, remove the threat, patch the vulnerability, and restore from clean backups.

<Note title="Account lockout and alerts">
Locking an account after several failures, plus alerting on success after failures, stops many brute-force attacks.
</Note>

<WorkedExample title="Count failures">
An auth log shows 37 failed logins for user 'jlee' from one IP in 2 minutes and no success. What is the likely attack, and has it succeeded?

1. Rapid repeated guesses on one account.

**Answer:** a brute-force attempt; it has not succeeded, but the IP should be blocked and the account reviewed.
</WorkedExample>

## On the practice exams

### Worked exam question 1

An administrator reviews this authentication log.

```text
Mar 03 02:10:44 sshd: Accepted password for chen from 192.0.2.229
Mar 03 02:14:01 sshd: Failed password for backup from 198.51.100.135
Mar 03 02:14:03 sshd: Failed password for backup from 198.51.100.135
Mar 03 02:14:05 sshd: Failed password for backup from 198.51.100.135
Mar 03 02:14:07 sshd: Failed password for backup from 198.51.100.135
Mar 03 02:14:09 sshd: Failed password for backup from 198.51.100.135
Mar 03 02:14:11 sshd: Failed password for backup from 198.51.100.135
Mar 03 02:14:13 sshd: Failed password for backup from 198.51.100.135
```

Which conclusion is best supported?

**Answer:** A brute-force attempt from 198.51.100.135 against backup has not yet succeeded

**Why:** Repeated failures with no successful login.

**Working:** 7 failed logins for backup from 198.51.100.135 in seconds; block the address and consider account lockout.

**Mistakes to avoid**

- A brute-force attack from 198.51.100.135 succeeded: Check whether the log shows an accepted login from that address.
- 192.0.2.229 is attacking the server: That address logged in once normally.
- The log shows only normal activity: 7 rapid failures from one address is abnormal.

### Free-response practice: Device Security Analysis: lab-srv03

An analyst is investigating the device lab-srv03 after an alert. Use the six sources below.

**Source 1: Security policy**

1. Files containing personal data must not be readable by users outside the owner's group.

2. Remote administration (SSH, port 22) is permitted only from the IT subnet 10.0.20.0/24.

3. Accounts are locked after 5 consecutive failed logins.

4. Only HTTPS (443) may be accepted from outside the organization.

**Source 2: Host firewall rules (inbound, first match)**

```text
#  Action  Source          Port
1  ALLOW   any             443
2  ALLOW   any             22
3  ALLOW   any             23
   (all other inbound traffic denied)
```

**Source 3: File permissions**

```text
-rw-r--r-- apatel staff  1820 notes.txt
-rw-r--rw- apatel staff 48211 grades.db
-rwxr-x--- apatel staff   902 backup.sh
```

**Source 4: Authentication log**

```text
02:13:58 sshd: Accepted publickey for apatel from 10.0.3.21
02:14:02 sshd: Failed password for admin from 203.0.113.78
02:14:04 sshd: Failed password for admin from 203.0.113.78
02:14:06 sshd: Failed password for admin from 203.0.113.78
02:14:08 sshd: Failed password for admin from 203.0.113.78
02:14:10 sshd: Failed password for admin from 203.0.113.78
02:14:14 sshd: Accepted password for admin from 203.0.113.78
02:16:40 sudo: admin : COMMAND=/bin/cat /home/apatel/grades.db
```

**Source 5: Active network connections**

```text
Proto  Local        Remote               State
tcp    lab-srv03:22   203.0.113.78:51544   ESTABLISHED
tcp    lab-srv03:443  10.0.3.40:60122      ESTABLISHED
```

**Source 6: Change request**

```text
Proposed: run "chmod 740 grades.db" and replace firewall rule 2 with: ALLOW 10.0.20.0/24 22
```

On the real exam, this question also includes six sources about a single device; here they are generated for practice.

**(a)** Identify one configuration on this device that violates the security policy. Cite evidence from the sources.

To earn the point: Identifies a policy violation with evidence. Model answer: grades.db has permissions rw-r--rw-, so others can read it (Source 3), violating policy 1. Also, rule 2 allows SSH from any source (Source 2), violating policy 2. Rule 3 allows port 23 from anywhere, violating policy 4.

**(b)** Describe the attack shown in the sources, citing specific evidence, and explain whether it succeeded.

To earn the point: Identifies a brute-force (password-guessing) attack. Model answer: 5 failed passwords for admin from 203.0.113.78 within seconds (Source 4).

To earn the point: Explains that it succeeded, with evidence. Model answer: An accepted password from the same address follows, the attacker read grades.db with sudo, and an SSH session from 203.0.113.78 is still established (Source 5).

To earn the point: Notes the failed control. Model answer: Account lockout after 5 failures (policy 3) did not happen: 5 failures were allowed.

**(c)** Describe the effect of running "chmod 740 grades.db" on who can access the file, and explain whether it brings the file into compliance.

To earn the point: Correctly interprets the new permissions. Model answer: 740 = owner rwx, group r--, others ---.

To earn the point: Explains compliance. Model answer: Others lose all access, so users outside the group can no longer read the personal data: it complies with policy 1.

**(d)** Describe how replacing firewall rule 2 with "ALLOW 10.0.20.0/24 22" would affect network traffic and users of the device.

To earn the point: Effect on attackers. Model answer: SSH from outside 10.0.20.0/24, including 203.0.113.78, would be denied by the implicit deny.

To earn the point: Effect on legitimate users. Model answer: IT staff on 10.0.20.0/24 can still administer the device; other internal users lose SSH access.

**(e)** Recommend one additional control to prevent a similar attack, and explain how it addresses the evidence.

To earn the point: A relevant control with justification. Model answer: Enforce account lockout and multifactor authentication or key-only SSH logins, so password guessing cannot succeed; alert on repeated failures.
